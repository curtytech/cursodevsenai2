01 / FUNDAMENTOS

O que é WebSocket?

WebSocket é um protocolo de comunicação que permite a troca de dados bidirecional (full-duplex) entre um cliente (client) e um servidor (server), por meio de uma conexão persistente.

Depois que a conexão é estabelecida, qualquer uma das partes pode enviar mensagens sem precisar iniciar uma nova requisição para cada troca. Isso é especialmente útil em aplicações que precisam atualizar informações em tempo real (real-time communication).

↗
Ideia central

Em vez de perguntar repetidamente “há novidades?”, o cliente mantém um canal aberto pelo qual o servidor também pode enviar dados quando necessário.

02 / CONTEXTO

Origem e objetivo

O WebSocket foi padronizado em 2011 pela RFC 6455. Ele surgiu para oferecer uma forma padronizada de comunicação contínua entre aplicações web, superando limitações do modelo tradicional de requisição e resposta do HTTP em cenários interativos.

2011Publicação da RFC 6455
2 viasCliente ↔ servidor
1 canalConexão persistente

Seu objetivo é permitir troca contínua de mensagens com menor overhead em cenários de comunicação frequente.

03 / CICLO DE CONEXÃO

Como funciona?

O ciclo básico pode ser entendido em três etapas:

01

Connection request

O cliente inicia uma conexão usando uma requisição HTTP especial e solicita a mudança de protocolo (Upgrade).

Upgrade: websocket
02

Handshake

Se a solicitação for aceita, o servidor responde com 101 Switching Protocols. A conexão passa a usar WebSocket.

HTTP/1.1 101 Switching Protocols
03

Data exchange

Cliente e servidor trocam mensagens pela conexão estabelecida. A comunicação continua até que um dos lados encerre o canal ou ocorra uma falha.

ws.send("Olá!")
Nota técnica: o handshake descrito é o mecanismo clássico do WebSocket sobre HTTP/1.1. Há também formas de estabelecer WebSocket sobre HTTP/2, definidas em especificações próprias.
04 / ARQUITETURA

Uma conexão, duas direções

Após o handshake, a comunicação ocorre por meio de frames (quadros de dados). O canal é full-duplex: cliente e servidor podem transmitir independentemente um do outro.

05 / COMPARAÇÃO

WebSocket vs. HTTP

Os protocolos atendem a necessidades diferentes. HTTP é a base de muitos sites e APIs; WebSocket é especialmente útil quando há troca frequente de dados nos dois sentidos.

Não é uma substituição

WebSocket não substitui HTTP. As duas tecnologias podem coexistir na mesma aplicação, cada uma atendendo ao tipo de comunicação mais adequado.

06 / ANÁLISE

Vantagens e desvantagens

＋ Vantagens

  • Comunicação bidirecional em tempo real.
  • Conexão persistente para trocas frequentes.
  • Menor overhead por mensagem em comparação com novas requisições HTTP repetidas.
  • Atualizações sem recarregar a página.
  • Suporte em navegadores modernos e várias linguagens.

− Desvantagens

  • Conexões abertas exigem gerenciamento.
  • Muitos clientes simultâneos podem consumir recursos.
  • Reconexão e recuperação de falhas precisam ser planejadas.
  • Autenticação, autorização e validação exigem atenção.

08 / IMPLEMENTAÇÃO

Exemplo prático

O exemplo utiliza JavaScript no navegador e a biblioteca ws no servidor Node.js. Os trechos abaixo formam uma demonstração simples de envio e resposta.

CLIENT.JS
const socket = new WebSocket("ws://localhost:8080");

socket.onopen = () => {
  console.log("Conexão estabelecida!");
  socket.send("Olá, servidor!");
};

socket.onmessage = (event) => {
  console.log("Mensagem:", event.data);
};

socket.onclose = () => {
  console.log("Conexão encerrada.");
};

socket.onerror = (error) => {
  console.log("Erro:", error);
};
SERVER.JS · NODE.JS
const WebSocket = require("ws");

const server = new WebSocket.Server({
  port: 8080
});

server.on("connection", (socket) => {
  console.log("Cliente conectado!");

  socket.on("message", (message) => {
    console.log("Recebido:", message.toString());
    socket.send("Mensagem recebida!");
  });

  socket.on("close", () => {
    console.log("Cliente desconectado.");
  });
});
new WebSocket()

Cria a conexão no cliente.

onopen

É executado quando a conexão abre.

send()

Envia uma mensagem pelo canal.

onmessage

Recebe mensagens do servidor.

onclose

Indica o encerramento da conexão.

onerror

Permite tratar eventos de erro.

Como executar: instale Node.js, crie uma pasta de projeto, execute npm install ws, salve o segundo trecho como server.js e inicie com node server.js. Depois, abra uma página local que execute o código do cliente. Em páginas servidas por HTTPS, utilize wss://.

Segurança em produção

Prefira wss:// (WebSocket Secure), use autenticação e autorização adequadas, valide as mensagens recebidas, limite tamanho e frequência de mensagens e verifique a origem da conexão quando aplicável.

09 / ENCERRAMENTO

Conclusão

WebSocket é uma tecnologia relevante para aplicações que precisam de comunicação contínua entre clientes e servidores. Sua conexão bidirecional permite troca de mensagens sem iniciar uma nova requisição para cada atualização.

Embora exija cuidados com conexões, escalabilidade e segurança, é uma solução adequada para chats, jogos multiplayer, notificações e monitoramento em tempo real. A escolha deve considerar as necessidades específicas de cada aplicação.

QUANDO A APLICAÇÃO PRECISA DE TROCA CONTÍNUA DE DADOS, WEBSOCKET É UMA OPÇÃO A CONSIDERAR.
