01 / FUNDAMENTOS

O que são FTP e SFTP?

Os dois protocolos permitem transferir arquivos, mas diferem principalmente na forma como protegem os dados durante a comunicação.

⇄
FILE TRANSFER PROTOCOL

FTP

Protocolo tradicional para enviar e receber arquivos entre cliente e servidor. Por padrão, não criptografa credenciais nem conteúdo.

Porta comum: 21Sem criptografia
MAIS INDICADO
⌑
SSH FILE TRANSFER PROTOCOL

SFTP

Protocolo de transferência que funciona sobre SSH. Criptografa a conexão e permite autenticação por senha ou chave SSH.

Porta comum: 22Criptografado
⛨
FTP OVER TLS

FTPS

É o FTP protegido por TLS. Mantém o funcionamento do FTP, adicionando criptografia e certificados digitais.

Porta comum: 21 explícitoTLS

03 / PRIMEIRO ACESSO

Como se conectar

Você precisa do endereço do servidor, usuário, método de autenticação e porta liberada. Solicite esses dados ao administrador.

01

Reúna os dados

Endereço do host, porta, usuário, senha ou chave SSH e diretório remoto autorizado.

02

Escolha um cliente

Use FileZilla para interface gráfica ou o terminal com o cliente OpenSSH para SFTP.

03

Valide a identidade

Na primeira conexão SSH, confira a impressão digital (fingerprint) com o administrador antes de confiar no servidor.

04

Transfira e confira

Envie ou baixe arquivos e confirme se o tamanho, nome e conteúdo chegaram corretamente.

04 / LABORATÓRIO

Comandos para usar na prática

Copie os exemplos e substitua os dados fictícios pelos dados reais do seu ambiente.

terminal — sftp
# Conectar ao servidor SFTP (porta padrão 22)
sftp -P 22 usuario@servidor.exemplo.com

# Listar arquivos no servidor
ls

# Enviar arquivo local para o servidor
put relatorio.pdf

# Baixar arquivo do servidor
get backup.zip

# Criar diretório remoto e entrar nele
mkdir documentos
cd documentos

# Encerrar a sessão
exit
terminal — ftp
# Conectar ao servidor FTP
ftp ftp.exemplo.com

# Depois de autenticar, listar arquivos
ls

# Definir modo binário para arquivos não textuais
binary

# Enviar e baixar arquivos
put relatorio.pdf
get retorno.csv

# Encerrar a sessão
bye
terminal — ssh-keygen
# Gerar um par de chaves Ed25519
ssh-keygen -t ed25519 -C "acesso-sftp"

# Exibir a chave pública para cadastramento no servidor
cat ~/.ssh/id_ed25519.pub

# Conectar usando a chave privada
sftp -i ~/.ssh/id_ed25519 -P 22 usuario@servidor.exemplo.com
ⓘ

Atenção: os comandos FTP tradicionais podem enviar usuário, senha e dados sem criptografia. Não use FTP puro em redes públicas ou na internet para informações sensíveis. Prefira SFTP ou FTPS.

05 / AUTOMAÇÃO

Script de envio com Python

Exemplo usando Paramiko para enviar um arquivo por SFTP. Instale a biblioteca antes de executar.

enviar_arquivo.py
# Instalação: pip install paramiko
import paramiko
from pathlib import Path

HOST = "servidor.exemplo.com"
PORT = 22
USERNAME = "seu_usuario"
KEY_FILE = Path.home() / ".ssh" / "id_ed25519"

ARQUIVO_LOCAL = "relatorio.pdf"
ARQUIVO_REMOTO = "/uploads/relatorio.pdf"

# Autenticação por chave SSH
chave = paramiko.Ed25519Key.from_private_key_file(str(KEY_FILE))

transport = paramiko.Transport((HOST, PORT))
try:
    transport.connect(username=USERNAME, pkey=chave)
    sftp = paramiko.SFTPClient.from_transport(transport)

    sftp.put(ARQUIVO_LOCAL, ARQUIVO_REMOTO)
    print("Upload concluído!")

    sftp.close()
finally:
    transport.close()

Guarde a chave privada com permissões restritas. Em produção, valide a chave de host do servidor; não desative a verificação de identidade.

06 / BOAS PRÁTICAS

Segurança em primeiro lugar

Uma transferência bem-sucedida também precisa proteger os dados e as credenciais.

♢

Prefira SFTP ou FTPS

Use protocolos criptografados para proteger credenciais e conteúdo transferido.

⌑

Proteja suas chaves

Nunca envie a chave privada por e-mail ou mensageiro. Compartilhe apenas a chave pública.

◉

Confira o servidor

Valide o fingerprint SSH na primeira conexão para reduzir o risco de servidor falso.

▣

Limite permissões

Use contas individuais e acesso somente às pastas necessárias para cada atividade.
