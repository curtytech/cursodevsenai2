Página 1 de 5 — Conceitos Fundamentais

O que é o HTTP Long Polling?

O HTTP Long Polling é uma técnica avançada de comunicação cliente-servidor projetada para emular o envio de dados em tempo real (Push) utilizando o protocolo HTTP padrão, superando a limitação nativa onde apenas o cliente pode iniciar uma comunicação.

1

1. Requisição Suspensa

O cliente faz uma requisição HTTP solicitando atualização. O servidor **não responde de imediato**: ele retém a chamada aberta aguardando novos dados.

2

2. Resposta Instantânea

No exato momento em que um evento ocorre no servidor (ou ao atingir um tempo limite de *timeout*), os dados são empacotados e enviados de volta.

3

3. Reconexão Imediata

Assim que recebe a resposta, o cliente processa as informações e **abre imediatamente uma nova requisição**, reiniciando a escuta ativa sem pausas.

Por que usar Long Polling ao invés de Polling Tradicional?

No Polling Tradicional, o cliente faz requisições em intervalos fixos (ex: a cada 2 segundos), gerando centenas de respostas `HTTP 200/304` vazias que consomem banda e processamento sem necessidade. O Long Polling elimina esse desperdício, mantendo o canal silencioso até que haja algo relevante a ser entregue.

Página 3 de 5 — Aplicações & Análise Técnica

Casos de Uso Práticos & Análise da Arquitetura

Descubra onde o Long Polling se destaca e conheça suas vantagens e pontos de atenção.

Chats Web

Mensagens entregues no momento em que são enviadas, muito usado em suporte ao cliente.

Notificações In-App

Alertas de novos e-mails, curtidas e avisos em painéis de usuários.

Status de Tarefas

Acompanhamento de relatórios pesados e conversões de arquivos no servidor.

Rastreamento GPS

Atualização periódica da posição de entregadores sem necessidade de WebSockets.

✓ Vantagens Principais
  • • Compatibilidade Total: Funciona em qualquer servidor proxy, firewall ou CDN sem requerer suporte a WebSockets.
  • • Sem Requisições Inúteis: Não desperdiça conexões enviando dados vazios a cada segundo.
  • • Fácil Implementação: Utiliza o comando `fetch()` padrão no frontend sem bibliotecas externas.
✕ Limitações & Desafios
  • • Overhead de Cabeçalhos: A cada reconexão, dados HTTP (cookies/tokens) precisam ser reenviados.
  • • Carga no Backend: Exige que o servidor consiga manter milhares de conexões assíncronas em espera simultaneamente.
  • • Canal Unidirecional: Para o cliente enviar dados enquanto escuta, ele precisa abrir uma nova requisição paralela.

Página 5 de 5 — Códigos Práticos

Exemplos de Código Prático

Implementação básica no Cliente (JavaScript Vanilla) e no Servidor (Node.js + Express). 

// Função assíncrona recursiva para escuta contínua
async function subscribeToUpdates() {
  try {
    // 1. Abre a requisição HTTP e aguarda o servidor responder
    const response = await fetch('/api/stream-updates');

    if (response.status === 504) {
      // Timeout de Gateway - reconecta sem erro
      await subscribeToUpdates();
      return;
    }

    if (response.ok) {
      // 2. Processa o dado entregue pelo servidor
      const data = await response.json();
      renderData(data);
    }
  } catch (error) {
    // Aguarda 3s antes de tentar em caso de queda de rede
    await new Promise(res => setTimeout(res, 3000));
  } finally {
    // 3. RECONEXÃO IMEDIATA: inicia um novo ciclo sem pausa
    await subscribeToUpdates();
  }
}

subscribeToUpdates();
const express = require('express');
const app = express();

let pendingConnections = [];

app.get('/api/stream-updates', (req, res) => {
  // 1. Retém o objeto de resposta `res` na fila de pendências
  pendingConnections.push(res);

  // 2. Timeout de segurança (ex: 30s)
  const timeoutId = setTimeout(() => {
    pendingConnections = pendingConnections.filter(conn => conn !== res);
    res.status(204).end();
  }, 30000);

  req.on('close', () => {
    clearTimeout(timeoutId);
    pendingConnections = pendingConnections.filter(conn => conn !== res);
  });
});

// Disparado quando ocorre um evento real no backend
function broadcastEvent(payload) {
  pendingConnections.forEach(res => res.json(payload));
  pendingConnections = [];
}

app.listen(3000, () => console.log('Servidor pronto!'));
