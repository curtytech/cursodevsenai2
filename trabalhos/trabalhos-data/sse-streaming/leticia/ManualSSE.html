Capítulo 01 • Conceito Central & Evolução do HTTP

Server-Sent Events (SSE)

Comunicação unidirecional em tempo real: o servidor empurra dados continuamente sobre uma única conexão HTTP.

Fluxo Arquitetural da Tecnologia
SSE Padrão HTML5 / HTTP
abre canal
Streaming Conexão Persistente
unidirecional
Servidor → Cliente Eventos, Notificações, Status

O Problema: HTTP Comum & Polling

Jeito Antigo

No HTTP tradicional, o cliente pede algo, o servidor responde e fecha a conexão na hora. Para simular tempo real, usava-se o Polling (perguntar a cada 3 segundos se há novidade).

Na Cafeteria (Polling): Você vai ao balcão a cada 2 minutos perguntar: "Meu café ficou pronto?". Gera milhares de respostas vazias e sobrecarrega o servidor.

A Solução Moderna: SSE Streaming

Tempo Real

Com SSE, o cliente abre uma única conexão HTTP de longa duração e permanece apenas em modo de escuta. O servidor empurra dados instantaneamente quando ocorrem.

Na Cafeteria (SSE): Você faz o pedido uma única vez, senta na mesa e o atendente vem até você avisar assim que o café fica pronto.
Capítulo 02 • Engenharia do Protocolo & Anatomia dos Pacotes

Como Funciona por Trás dos Panos?

O ciclo de vida completo da conexão persistente e a estrutura interna das mensagens.

01

Requisição via API EventSource

No frontend, o navegador instancia new EventSource('/stream'). Ele dispara uma requisição HTTP GET padrão contendo o cabeçalho Accept: text/event-stream para abrir o túnel de leitura.

02

Os 3 Cabeçalhos HTTP Vitais

Obrigatórios

Configurados na resposta do servidor para manter o canal vivo sem cache:

Content-Type: text/event-stream // Ativa streaming
Cache-Control: no-cache // Bloqueia cache
Connection: keep-alive // Mantém porta aberta
03

Anatomia do Pacote & Tipos de Eventos

Mensagens em texto puro encerradas obrigatoriamente com dupla quebra de linha (\n\n):

id: 2048 // Identificador único do evento
event: alerta-estoque // Nome customizado (padrão: message)
data: {"produto": "Jaqueta", "qtd": 3}\n\n
04

Reconexão Nativa & Last-Event-ID

Se a rede cair ou o servidor reiniciar, o navegador aguarda ~3s e reconecta automaticamente sem nenhuma linha extra de código no cliente.

Ao voltar, o browser envia o header Last-Event-ID para o servidor retomar exatamente do último pacote perdido.
Capítulo 03 • Aplicações no Mercado & Decisão Arquitetural

Casos de Uso & SSE vs. WebSockets

Dashboards & Métricas

Monitoramento de servidores/CPU, gráficos financeiros, bolsa de valores e cotações de criptomoedas ao vivo.

Feeds & Notificações

Alertas em tempo real (sininhos), atualização de timelines de notícias e placares esportivos instantâneos.

Streaming de IA (LLMs)

Padrão usado por ChatGPT e Gemini para exibir respostas palavra por palavra (efeito typing) em tempo real.

Status de Pedidos

Rastreamento de etapas de entregas em apps de delivery, progresso de exportações e filas de processamento.

Comparativo Técnico: SSE vs. WebSockets

Regra de ouro: se o cliente apenas recebe dados em tempo real, prefira SSE.
Característica SSE (Server-Sent Events) WebSockets
Direção do Fluxo Unidirecional (Servidor → Cliente) Bidirecional (Servidor ↔ Cliente)
Protocolo HTTP / HTTPS Padrão (passa fácil por firewalls) Protocolo próprio (ws:// ou wss://)
Reconexão Nativa Sim (Automática via EventSource) Não (Exige implementação manual)
Complexidade Baixa (Leve e nativo nos navegadores) Média / Alta (Gerenciamento de estado e conexões)
Melhor Uso Feeds, notificações, dashboards, status, IA Chats em tempo real, jogos multiplayer, edição colaborativa
Capítulo 04 • Implementação Real & Teste Interativo

Código Prático & Simulador SSE Ao Vivo

1. Servidor (Node.js + Express)
Emissor SSE 
app.get('/api/stream', (req, res) => {
  // 1. Cabeçalhos vitais para manter o streaming ativo
  res.setHeader('Content-Type', 'text/event-stream');
  res.setHeader('Cache-Control', 'no-cache');
  res.setHeader('Connection', 'keep-alive');

  // 2. Envia eventos periódicos com dupla quebra (\n\n)
  const timer = setInterval(() => {
    const payload = { status: 'Ativo', hora: new Date().toLocaleTimeString() };
    res.write(`event: status-update\n`);
    res.write(`data: ${JSON.stringify(payload)}\n\n`);
  }, 2000);

  // 3. Libera recursos quando o cliente desconectar
  req.on('close', () => clearInterval(timer));
});
2. Cliente (JavaScript Nativo EventSource)
Ouvinte SSE 
// 1. Conecta ao endpoint SSE (sem bibliotecas externas)
const evtSource = new EventSource('/api/stream');

// 2. Escuta eventos personalizados enviados pelo servidor
evtSource.addEventListener('status-update', (event) => {
  const dados = JSON.parse(event.data);
  console.log('Evento recebido:', dados);
});

// 3. Reconexão automática nativa em caso de queda
evtSource.onerror = () => console.warn('Reconectando automaticamente...');
