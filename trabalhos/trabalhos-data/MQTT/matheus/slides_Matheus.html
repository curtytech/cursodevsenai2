00_VISÃO_GERAL

Protocolo MQTT & Arquitetura Pub/Sub

O padrão definitivo de comunicação para Internet das Coisas (IoT) e Indústria 4.0.

◈ CONCEITO CHAVE

Protocolo ultraleve de mensagens. Substitui as conexões diretas por um modelo onde todos se comunicam via intermediário (Broker).

◈ USO PRINCIPAL

Ideal para redes instáveis e hardware com limitações de processamento (ESP32, Arduino, CLP Industriais).

01_FUNDAMENTOS

O que é MQTT e origem?

O MQTT (Message Queuing Telemetry Transport) foi criado em 1999 pela IBM para monitorar oleodutos no deserto via satélite, cenário onde a internet era cara e caía frequentemente.

Extremamente Leve

Cabeçalho minúsculo de apenas 2 Bytes (contra centenas do HTTP). Economia drástica de banda de rede.

Baixo Consumo

Mantém sensores remotos e baterias operando por longos períodos sem a necessidade de recarga.

Redes Instáveis

Projetado para manter a integridade dos dados em conexões oscilantes (3G, 4G, Satélite ou LoRa).

ISO/IEC 20922 Standard02 / 08
02_ARQUITETURA

A Arquitetura Publish / Subscribe

No MQTT, os dispositivos nunca conversam diretamente. Tudo é mediado pelo Broker.

[ 🌡️ SENSOR TEMP. ] --- PUBLICA: "fabrica/temp" ---> [ ☁️ BROKER CENTRAL ] (Publicador) (Mosquitto / HiveMQ) │ [ 💻 PAINEL WEB ] <--- ASSINA: "fabrica/temp" <-------------┘ (Assinante)
Desacoplamento Absoluto: O sensor (Publisher) e o painel (Subscriber) não precisam conhecer o IP um do outro, nem estarem ativos no mesmo exato momento.
O Broker gerencia as filas e a distribuição03 / 08
03_ENDEREÇAMENTO

Tópicos e Filtros (Wildcards)

As mensagens são organizadas hierarquicamente usando barras, como diretórios de um PC:

senai / niteroi / galpao1 / motor3 / temperatura

Sinal de Mais (+)

Substitui um único nível da árvore.

Ex: senai/+/galpao1/... escuta os galpões 1 de todos os campi do Senai.

Sinal de Cerquilha (#)

Substitui todos os níveis seguintes.

Ex: senai/niteroi/# recebe absolutamente todos os dados do campus de Niterói.

Wildcards tornam a assinatura de sensores escalável04 / 08
04_CONFIABILIDADE

Níveis de Qualidade de Serviço (QoS)

O MQTT permite ajustar o rigor da entrega de cada mensagem através do QoS:

QoS 0
At most once

"Dispara e esquece". Alta performance, mas se a conexão falhar no momento, o dado é perdido.

QoS 1
At least once

Garante a entrega (requer PUBACK). Por conta de reenvios, a mesma mensagem pode chegar duplicada.

QoS 2
Exactly once

Entrega mais segura. Usa handshake de 4 vias para garantir que a mensagem chegue uma única vez.

Adapte o QoS conforme a criticidade do sistema05 / 08

06_CÓDIGO_FONTE

Implementação (Node.js)

publisher.js 
const mqtt = require('mqtt');
const client = mqtt.connect('mqtt://broker.hivemq.com');

client.on('connect', () => {
  // Publica a temperatura a cada 2 seg
  setInterval(() => {
    client.publish('senai/fabrica/temp', '24.5');
  }, 2000);
});
subscriber.js 
const mqtt = require('mqtt');
const client = mqtt.connect('mqtt://broker.hivemq.com');

client.on('connect', () => {
  // Assina o tópico desejado
  client.subscribe('senai/fabrica/temp');
});

client.on('message', (topic, msg) => {
  console.log(`Temp recebida: ${msg} °C`);
});
Requisito: npm install mqtt07 / 08
07_ENCERRAMENTO

Aplicações Reais & Segurança

🌐 Onde é usado?

  • Indústria 4.0: Monitoramento de motores e CLP.
  • Smart Homes: Dispositivos no Home Assistant.
  • Telemetria: Rastreadores GPS em Frotas.
  • Saúde: Monitoramento de pacientes à distância.

🔒 Segurança em Produção

O MQTT padrão trafega em texto puro. Em sistemas de produção, é imperativo usar a porta 8883 (MQTTS) com criptografia SSL/TLS, garantindo autenticação com login e senha no acesso ao Broker.
