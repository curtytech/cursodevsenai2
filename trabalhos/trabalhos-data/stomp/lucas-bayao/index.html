01 / FUNDAMENTOS

O que é STOMP?

STOMP significa Simple (ou Streaming) Text Orientated Messaging Protocol. É um protocolo de texto, simples e interoperável, usado para permitir que clientes e servidores de mensageria troquem mensagens por meio de uma conexão.

01 //

Protocolo

Define um formato comum para estruturar comandos, cabeçalhos e corpos de mensagens.

02 //

Mensageria

Permite que produtores enviem mensagens e consumidores recebam atualizações por destinos.

03 //

Interoperável

Clientes escritos em linguagens diferentes podem conversar com um broker compatível.

Importante: STOMP não é, por si só, um servidor nem um transporte de rede. Ele define o formato e os comandos das mensagens. Normalmente funciona sobre TCP ou sobre WebSocket, com um broker fazendo a intermediação.

Uma comparação simples

Imagine uma central de distribuição: você não precisa conhecer cada pessoa que receberá o aviso. Envia a mensagem para um endereço (destino), e o sistema de mensageria cuida da distribuição conforme as regras daquele destino.

02 / ARQUITETURA

Quem conversa com quem?

Em uma arquitetura comum, o cliente não precisa enviar a mensagem diretamente para cada outro cliente. O broker recebe, encaminha e entrega mensagens aos consumidores inscritos.

Produtorenvia SEND
──▶
Brokerroteia mensagens
──▶
Consumidorrecebe MESSAGE
FLUXO SIMPLIFICADO DE UMA MENSAGEM

Produtor (publisher)

Aplicação que publica uma mensagem em um destino usando o comando SEND.

Consumidor (subscriber)

Aplicação que se inscreve em um destino com SUBSCRIBE para receber mensagens.

O broker é responsável por intermediar a comunicação. O significado de destinos como /topic/... e /queue/..., assim como suas garantias de entrega, depende da implementação do servidor.
03 / ESTRUTURA

Anatomia de um frame

A unidade básica do STOMP é o frame. Ele contém um comando, cabeçalhos opcionais, uma linha em branco e, quando permitido, um corpo. O frame termina com um byte NULL.

ESTRUTURA GERAL · STOMP 1.2
COMMAND
header1:value1
header2:value2

Corpo da mensagem^@

1. Comando

Indica a ação, por exemplo SEND, SUBSCRIBE ou MESSAGE.

2. Cabeçalhos

Metadados no formato chave:valor, como destino, ID e tipo do conteúdo.

3. Corpo

Conteúdo da mensagem. É separado dos cabeçalhos por uma linha em branco.

Detalhe técnico: em STOMP 1.2, as linhas terminam com LF ou CRLF. O terminador NULL é representado nos exemplos como ^@; essa representação é apenas ilustrativa.

Exemplo: enviar uma mensagem

FRAME SEND 
SEND
destination:/queue/avisos
content-type:text/plain

Olá, equipe!^@

Leitura: o comando SEND envia o corpo “Olá, equipe!” para o destino /queue/avisos. O broker interpreta o destino conforme sua configuração.

04 / COMANDOS

O vocabulário do protocolo

Os comandos são palavras-chave que definem o que o cliente ou o servidor está fazendo. Estes são os principais comandos da especificação STOMP 1.2.

Comando Direção típica Função
CONNECT / STOMP Cliente → Broker Inicia a sessão STOMP.
CONNECTED Broker → Cliente Confirma a conexão e informa a versão negociada.
SEND Cliente → Broker Publica uma mensagem em um destino.
SUBSCRIBE Cliente → Broker Cria uma inscrição em um destino.
UNSUBSCRIBE Cliente → Broker Remove uma inscrição existente.
MESSAGE Broker → Cliente Entrega uma mensagem ao consumidor.
ACK / NACK Cliente → Broker Confirma ou rejeita o processamento de uma mensagem.
RECEIPT Broker → Cliente Confirma o processamento de um frame que solicitou recibo.
ERROR Broker → Cliente Informa um erro; normalmente a conexão é encerrada em seguida.
DISCONNECT Cliente → Broker Solicita encerramento organizado da sessão.

Comandos de transação

A especificação também define BEGIN, COMMIT e ABORT para iniciar, confirmar e cancelar transações. O suporte e os efeitos práticos dependem do broker.

05 / NA PRÁTICA

Ciclo de comunicação

Veja a sequência típica: primeiro a conexão é estabelecida, depois o consumidor se inscreve e o produtor publica.

Conectar

O cliente envia CONNECT com a versão e o host desejados. O broker responde CONNECTED.

Inscrever

O consumidor envia SUBSCRIBE com um ID e um destino para começar a receber mensagens.

Publicar

O produtor envia SEND indicando o destino e o conteúdo da mensagem.

Entregar

O broker encaminha a mensagem e envia um frame MESSAGE ao consumidor inscrito.

Confirmar (quando necessário)

Se a inscrição exigir confirmação manual, o cliente envia ACK após processar a mensagem.

Desconectar

O cliente envia DISCONNECT. Para um encerramento organizado, pode solicitar e aguardar um RECEIPT.

06 / TRANSPORTE

STOMP + WebSocket

WebSocket mantém uma conexão bidirecional entre navegador e servidor. STOMP pode usar essa conexão como transporte, adicionando uma linguagem padronizada de comandos e mensagens.

WebSocket

É o canal de comunicação persistente. Permite que cliente e servidor enviem dados um ao outro sem abrir uma requisição HTTP para cada mensagem.

STOMP

É o protocolo de mensageria que organiza o conteúdo enviado pelo canal: conexão, destinos, inscrições, confirmações e mensagens.

Navegadoraplicação JS
⇄
WebSockettransporte
⇄
STOMP Brokermensageria
Não confunda: WebSocket e STOMP não são concorrentes. WebSocket fornece o canal; STOMP define como a comunicação de mensageria é organizada sobre esse canal. Também é possível usar STOMP diretamente sobre TCP.
07 / MÃO NA MASSA

Exemplo com JavaScript

No navegador, uma biblioteca cliente STOMP pode cuidar da montagem e interpretação dos frames. O exemplo abaixo usa a biblioteca @stomp/stompjs e pressupõe que exista um endpoint WebSocket STOMP ativo no servidor.

TERMINAL
npm install @stomp/stompjs

Em projetos com bundler, instale o pacote pelo npm. Também é possível carregar uma versão compatível por CDN, conforme a documentação da biblioteca.

client.js 
import { Client } from '@stomp/stompjs';

const client = new Client({
  brokerURL: 'ws://localhost:8080/stomp',
  reconnectDelay: 5000,
  onConnect: () => console.log('Conectado!'),
  onStompError: frame => console.error(frame.body)
});

client.activate();

Troque a URL pelo endpoint WebSocket STOMP real do seu broker. A rota e o tipo de conexão dependem da configuração do servidor.

PUBLICAR MENSAGEM 
client.publish({
  destination: '/topic/avisos',
  body: JSON.stringify({ texto: 'Olá, STOMP!' }),
  headers: { 'content-type': 'application/json' }
});

O destino /topic/avisos é ilustrativo. Use o padrão de destino que o seu broker configurou.

RECEBER MENSAGENS 
const subscription = client.subscribe(
  '/topic/avisos',
  message => {
    const dados = JSON.parse(message.body);
    console.log('Recebido:', dados.texto);
  }
);

// Quando não precisar mais receber:
// subscription.unsubscribe();

A função de callback é executada quando chega uma mensagem. Trate o corpo de acordo com o formato combinado entre produtor e consumidor.

Atenção: este é um exemplo de cliente, não um sistema completo pronto para produção. Você ainda precisa configurar um broker, habilitar o endpoint WebSocket/STOMP, definir autenticação, permissões e destinos. Não exponha credenciais privadas no JavaScript do navegador.
08 / QUALIDADE

Boas práticas

Autenticação

Use TLS (WSS em produção) e autenticação configurada no broker. Nunca deixe credenciais sensíveis expostas no front-end.

Reconexão

Planeje reconexões e restauração de inscrições após quedas de rede.

Confirmação

Escolha o modo de ACK conforme a criticidade e o comportamento de reentrega desejado.

Validação

Valide o formato e o tamanho das mensagens antes de processá-las.

Destinos

Documente os nomes dos destinos e confirme sua semântica na documentação do broker.

Observabilidade

Registre erros, desconexões e falhas de processamento sem gravar segredos ou dados sensíveis.

09 / DIAGNÓSTICO

Problemas comuns

Sintoma Causa possível O que verificar
Conexão recusada Endpoint incorreto ou broker indisponível. URL, porta, serviço e suporte a WebSocket.
Erro ao negociar versão Cliente e servidor sem versão STOMP em comum. Cabeçalho accept-version e versão do broker.
Não recebe mensagens Destino errado ou inscrição não criada. Confirmação da conexão, destino e permissões.
Mensagem rejeitada Frame inválido ou cabeçalho obrigatório ausente. Comando, sintaxe, destino e corpo.
Desconexão inesperada Rede instável, heartbeat ou timeout. Configuração de heartbeat e logs do broker.
